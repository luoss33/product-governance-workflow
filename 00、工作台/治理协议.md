# 治理协议

## 事实链和状态

| 位置 | 作用 |
| --- | --- |
| `01、来源` | 按原文保存纪要、调研和评审资料，登记可追溯的来源位置 |
| `02、决策` | 记录有明确人工确认依据的业务决策 |
| `03、当前规范` | 每个主题一份现行规范，在当前状态表登记一次 |
| `04、资产` | 流程、字段、页面、原型和 PRD 消费现行规则 |
| `05、Wiki`、`99、历史` | 提供查阅和追溯，引用当前权威材料 |

来源记录可以保留草稿、待确认、会议结论、已确认或已废止等证据状态。会议材料中的建议仍是候选规则。发现资产和规范不一致时，从现行规则和可核验来源追溯。资料缺口写「当前资料未覆盖」。

业务规则（BR）的状态为 `CONFIRMED`（生效）、`PROVISIONAL`（暂定）、`OPEN`（待定）、`CONFLICT`（有冲突）、`SUPERSEDED`（已替代）。交付状态另记为草稿、待评审、已确认或已废止。资产同步状态见下文。

记录可用 `SRC-主题代号-序号`、`DEC-主题代号-序号`、`BR-主题代号-序号`、`ART-主题代号-序号`、`OPEN-主题代号-序号` 互相引用。沿用工作区已有的编号约定。

## 采集与对齐

记录来源原话及文件与小节、页码或时间点。区分已知事实、现行规则、用户目标、候选方案、资料缺口和纯表达变化。目标主题已有规范时，标明具体受影响规则以及新增、替代或冲突的部分。

方案优先由 [产品变更工作流](../.agents/skills/product-change-workflow/SKILL.md)组织。一次声明本批计划同步的普通工作资产、需要具体授权的锁定资产、未覆盖事项。答案会改变本批结果且现有证据无法裁决时，才向用户提问。

## 确认

向用户展示可独立判断的确认文本，包含：

- 来源原话和位置、AI 对输入的理解。
- 拟固化的完整规则。说明适用角色、条件、动作及结果，并标清变更或沿用的规则和例外。
- 会替代哪些旧规则，影响哪些资产，有哪些范围尚未覆盖，以及本批准备同步什么。

用户的回复需要明确指向已展示的规则文本或编号批次。对齐和确认可以在同一次回复完成。收到「继续」或「生成文件」时，先核对它是否确指完整规则；若表达只是继续工作，规则仍待确认。回复增加条件、例外或变更范围时，重新比较 受影响规则并展示调整后的完整文本。

用户要求先出方案时保持只读；用户授权留档时，可在确认前保存原始输入和待确认项，将候选维持在相应证据状态。

## 固化

1. 确认证据有效、完整规则已获明确确认且当前规范可以唯一定位。全新主题可以在首次确认后建立现行规范和登记行。
2. 用[决策模板](模板/决策记录.md)保存逐字回复、准确来源、确认文本、范围和未覆盖项。新增或替代 BR 时保留旧记录与替代关系。
3. 更新唯一现行规范和相关登记，记录受影响资产和待同步事项。更新共享文件前检查读取基线；冲突时先重读再合并，分步失败时根据实际落点继续核对。
4. 沿来源、决策、规则和实际落点复核，遇到新增的限制或适用范围变化时返回对齐。

## 资产同步与交付

| 同步状态 | 何时使用 |
| --- | --- |
| `Updated` | 本批已按规则修改且完成相应验证 |
| `No Impact` | 经影响判断，资产与本批无关 |
| `Dirty` | 已知存在差异，等待同步或锁定资产授权 |
| `Paused` | 用户明确暂停同步，注明恢复条件 |
| `Unknown` | 缺证据、未检查或验证失败 |

普通工作资产按已声明且获授权的范围同步。锁定资产的具体文件和变更须获授权；未获授权且已知受影响时登记为 `Dirty`。正式交付确认以具体资产、版本和范围为准。对涉及字段、按钮、角色、状态、权限或任务归属的删改，记录其保留、移位或取消，并关联相应确认。

验证至少核对本批依据、替代关系、实际落点和相关场景结果。总结记录实际已验证、待更新、暂停、待确认的事项；存在 `Dirty` 或 `Unknown` 时，逐项说明未完成。结构检查通过只证明对应文件和引用满足检查条件。

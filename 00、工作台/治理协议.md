# 治理协议

## 事实链和状态

| 位置 | 作用 |
| --- | --- |
| `01、来源` | 按原文保存纪要、调研和评审资料，登记可追溯的来源位置 |
| `02、决策` | 记录有明确人工确认依据的业务决策 |
| `03、当前规范` | 每个主题一份现行规范，在当前状态表登记一次 |
| `04、资产` | 流程、字段、页面、原型和 PRD 消费现行规则 |
| `05、Wiki`、`99、历史` | 提供查阅和追溯，引用当前权威材料 |

日常业务口径分为待确认、已确认、已废止。草稿、会议暂定和冲突按待确认范围处理，来源记录保留材料原有的证据等级。AI 推荐、会议建议和资产现状经分类、比较与人工确认后，才形成生效规则。资料缺口写「当前资料未覆盖」。

底层 BR 状态沿用 `CONFIRMED`（已确认）、`PROVISIONAL / OPEN / CONFLICT`（待确认）、`SUPERSEDED`（已替代）。记录可用 `SRC / DEC / BR / ART / OPEN-主题代号-序号` 互相引用，沿用工作区已有编号。

## 现行规范薄账本

现行规范记录决定系统行为的对象边界、角色权限、状态流转、主流程、任务、字段规则、通知、异常与外部系统，以及待确认红线和当前资产入口。规则写清条件、动作和结果，确认依据指向决策。

界面排版、控件间距、按钮话术和配图说明在当期主交付物中维护。原有长规范中的有效业务事实继续保留，随着相关规则的真实修订逐步收敛。规范正文按业务主题组织，变更原因和确认历史放在决策记录中。[薄账本模板](模板/当前规范.md)

## 采集与对齐

记录来源原话及文件与小节、页码或时间点。区分已知事实、现行规则、用户目标、候选方案、资料缺口和纯表达变化。已有主题标明具体受影响规则以及新增、替代或冲突的部分。

方案由[产品变更工作流](../.agents/skills/product-change-workflow/SKILL.md)组织，随本批同步范围说明当前阶段、主交付物、普通工作资产、需要授权的锁定资产和未覆盖事项。答案会改变本批结果且现有证据无法裁决时，才向用户提问。

## 确认

向用户展示可独立判断的确认文本，包含：

- 来源原话和位置、AI 对输入的理解。
- 拟固化的完整规则，说明适用角色、条件、动作及结果，并标清变更或沿用的规则和例外。
- 会替代哪些旧规则，影响哪些资产，有哪些范围尚未覆盖，以及本批准备同步什么。

用户的回复需要明确指向已展示的规则文本或编号批次。对齐和确认可以在同一次回复完成。收到「继续」或「生成文件」时，核对它是否确指完整规则。回复增加条件、例外或变更范围时，重新比较受影响规则并展示调整后的完整文本。

用户要求先出方案时保持只读。用户授权留档时，可在确认前保存原始输入和待确认项，将候选维持在相应证据状态。

## 固化

1. 核对完整规则的确认证据和唯一现行规范。全新主题可以在首次确认后建立规范和登记行。
2. 用[决策模板](模板/决策记录.md)保存逐字回复、准确来源、确认文本、范围和未覆盖项。替代 BR 时保留旧记录与替代关系。
3. 将核心业务变化写入薄账本，更新真正变化的登记项，并按本批阶段和范围同步主交付物。共享文件写前检查读取基线，冲突时先重读再合并，分步失败时按实际落点继续核对。
4. 沿来源、决策、规则和实际落点复核。发现新增的限制或适用范围变化时，返回对齐。

## 按阶段维护主交付物

同一主题在同一阶段集中维护 1～2 个主交付物，将现行规范与当期评审载体配合使用。

| 当前阶段 | 日常维护重点 |
| --- | --- |
| 方案对齐 | 规范薄账本＋原型或主流程图。使用 Markdown 页面方案评审时，以该方案为当期载体。 |
| PRD 定稿 | 规范薄账本＋PRD。Word 的细表和排版在送审前集中整理。 |
| PRD 稳定后 | 按已确认且稳定的 PRD 更新测试用例，记录所依据的版本。 |

零散规则确认落入薄账本和当期主交付物。已明确影响但暂未更新的活动资产记为 `Dirty`。用户明确暂停、指定待主资产定稿后再同步的资产，以及已完成使命的阶段过渡文件，登记到当前资产表的「锁定基线与阶段过渡资产」区，以 `Paused` 标明暂停范围和恢复条件，原文件保留。

暂停期间保留上次同步依据。恢复维护时再核对待处理的变更范围和文件现状。用户锁定文件按具体资产、变更和授权处理。已有任务明确要求的交付范围按用户指令执行。

## 资产同步与交付

| 同步状态 | 日常显示与含义 |
| --- | --- |
| `Updated / No Impact` | ✅ 已同步。实际修改并验证，或判断该批对资产无影响。 |
| `Dirty` | 🟠 待更新。已知有差异等待同步。 |
| `Paused` | ⏸️ 暂不维护。按约定等待恢复。 |
| `Unknown` | ❓ 待核对。缺证据、未检查或验证失败。 |

同步状态和最近同步决策以[当前资产](当前资产.md)为准。资产说明保存身份、规则落点和必要验证摘要，引用登记结果。

交付阶段使用草稿、待评审、正式交付、用户确认只读基线。正式交付绑定具体资产、版本、范围及验收依据，只读基线还须遵守其锁定授权。业务规则已确认、文件已同步和用户接受交付分别记录。

旧登记中的「已确认」按具体版本的交付验收依据解释。被替代的旧版本保留「已废止」等历史标记并移出活动资产。现有记录随真实维护渐进调整。

普通工作资产按已声明且获授权的范围同步。未获授权且已知受影响的锁定资产登记为 `Dirty`。对涉及字段、按钮、角色、状态、权限或任务归属的删改，记录保留、移位或取消及其确认依据。

验证核对本批依据、替代关系、实际落点和相关场景。结尾交代已同步、待更新、暂不维护和待核对项。结构检查、业务场景验证与正式交付验收按各自范围记录。存在活动 `Dirty / Unknown` 时说明未完成项，暂停资产按约定处理。

治理维护复用现有记录和验证摘要，按实际变化更新。新增治理检查、状态或强制回执，以已经出现的业务口径错误或交付返工为依据。

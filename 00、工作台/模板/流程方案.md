# 流程方案

在绘制流程图或制作其他流程资产前，先用业务语言说明已确认的流程骨架。关键走向尚未确认时，把它列为待确认事项。

## 一句话主线

`起点 → 核心处理 → 关键分支 → 结束`

## 流程骨架

| 阶段 | 处理角色 | 输入或前置 | 核心动作 | 系统结果 | 下一步 | 分支或异常 |
|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |

## 关键分支

| 判断条件 | 判断角色 | 分支结果 | 任务或状态影响 | 确认依据 |
|---|---|---|---|---|
|  |  |  |  |  |

## 退回、撤回、转办与异常

| 场景 | 发起角色 | 后续去向 | 数据处理 | 状态或待办影响 | 确认依据 |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

## 当前需要确认

填写用户需要审阅的业务走向、处理角色和异常分支。图形布局属于表达方式，不应改变已确认语义。
